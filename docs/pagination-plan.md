# 分页表格自动翻页采集方案（提案，未实现）

现状：分页表格须用户手动翻页加载数据后再选表导出（v2.4 点击放行为此铺路）；虚拟滚动表格已支持自动滚动采集（virtual.js）。
目标：带分页控件的表格，扩展自动逐页翻页采集全部行，体验对齐虚拟滚动表格（点一次采全量）。
结论：**技术可行**。算法层约 70% 复用现有虚拟采集设施，成本集中在分页控件识别与选区管理改造；识别通用性风险经「自动识别 + 用户指定兜底」混合策略化解。

## 已确认决策

| 决策点 | 结论 |
|---|---|
| 功能范围 | 点击式分页（下一页按钮）；滚动加载（infinite scroll）由现有虚拟采集覆盖，不在本方案 |
| 识别策略 | 三层：组件特征类适配器（自动）→ 语义启发（自动）→ 用户指定翻页按钮（兜底，保底 100% 可用） |
| 触发方式 | 非自动劫持：点选带分页器表格后提供「采集全部页」入口（用户只想导当前页时不受扰） |
| 采集引擎 | 复用「逐窗口采集 + 相邻重叠合并 + 行签名」算法，窗口粒度从滚动窗口换成页 |
| 中止与停止 | 复用 genToken 代际令牌与「停止采集」按钮；停止条件三重判定（按钮 disabled / 无新行 / 页数上限） |
| 权限 | 零新增：activeTab + scripting 下内容脚本编程式点击分页按钮，无权限变更 |
| 模块形态 | 新增 `extension/content/pagination.js`（识别 + 采集调度），注入序置于 virtual.js 之后 |
| 滚动翻页器二期再议 | el-pagination 等带页码跳转输入框的组件，首版只认「下一页」按钮 |

## 识别策略（三层）

### 第一层：组件特征类适配器（高置信，自动）

复用 GRID_ADAPTERS 注册表模式（table.js），每组件一个适配器，特征类稳定、识别即精确到「下一页」按钮并可取总页数：

| 组件 | 根特征类 | 下一页按钮 | disabled 态 | 总页数来源 |
|---|---|---|---|---|
| Element Plus | `.el-pagination` | `.btn-next` | `.disabled` 类 | `.el-pagination__total` 文本 |
| Ant Design | `.ant-pagination` | `.ant-pagination-next` | `aria-disabled="true"` + `.ant-pagination-disabled` | `.ant-pagination-item` 序号最大值 |
| AG Grid | `.ag-paging-panel` | `[aria-label="Next"]` | `aria-disabled` | `.ag-paging-panel` 文本 |

### 第二层：语义启发（中置信，自动）

表格附近（同容器或下方固定距离内）找「下一页」语义的可点击元素：文本匹配（下一页/下页/next/>/›）、`aria-label="next"`、`rel="next"`；须同时具备可识别的 disabled 表现（`[disabled]` / `.disabled` / `aria-disabled="true"`）。命中即自动可用，失败静默降级到第三层。

### 第三层：用户指定翻页按钮（兜底）

前两层未命中 → 工具栏提供「指定翻页按钮」入口，进入子选择模式：

- 悬浮高亮放宽到任意元素（复用现有高亮层，不再限于表格根）；
- 用户点击目标控件 → 记录定位器，回到正常选择模式，「采集全部页」变为可用；
- 子模式拦截**所有**点击并提示「点击翻页按钮，Esc 取消」；Esc/取消退出不破坏已有选区；
- 交互骨架与现有选择模式同构（悬浮高亮 + 点选 + Esc 退出），零学习成本。

## 跨页重定位（指定元素的核心难点）

组件库翻页常整段重建 DOM，用户点的元素引用第二页即失联。记录**定位器**而非引用：

- 定位器 = tag + 特征类 + 规范化文本 + 相对表格根的位置（前/后、距离档位）；
- 每页翻完后按定位器重新解析；解析失败 → 中止采集，已采页保留，toast 说明原因；
- 与 persist.js 指纹定位同一类问题（结构与文本而非引用），实现思路借鉴、代码不复用；
- 可选二期：定位器按页面键存入 persist 同体系，同页下次自动恢复。

## 采集流程

```
点选表格（识别到分页器 / 已指定按钮）
  → 「采集全部页」
  → 记录起始页码与滚动位置
  → 循环：extractTable 当前页 → overlapLen 合并（页间无重叠时 k=0 直接拼接）
          → 校验表头指纹（tableKeyOf，防翻到结构不同的视图）
          → 点击下一页（豁免 v2.4 链接拦截）
          → 等待渲染（新表格根出现 + 行数>0 + 稳定两帧，超时补等）
  → 停止：下一页 disabled / 总页数已到 / 连续 2 页无新行 / 硬上限 500 页
  → 回到起始页（按页码回退或点「首页」，失败 toast 提示手动返回）
  → 快照入 snapshots Map（与虚拟采集同构，列设置面板可取样）
```

- 逐页取值走 `openBatch` 批量两阶段（cell.js），行签名复用 `overlapLen`（virtual.js）；
- 采集期间锁交互、hint 显示「第 i/N 页，已采集 M 行」，与虚拟采集一致。

## 停止条件（以行为而非结构为准）

| 判定 | 说明 |
|---|---|
| 下一页 disabled | 第一/二层有结构态时优先；第三层指定的按钮不一定有，仅作辅助 |
| 连续 2 页无新行 | 行签名比对，页间完全相同 = 到底（核心判定，覆盖全部来源） |
| 总页数 | 适配器/分页器文本（「第 2/10 页」）解析得到时显示进度并参与判定 |
| 硬上限 | 500 页防死循环（循环加载/异常页面），触顶中止并保留已采数据 |

## 选区管理改造（结构性改动，最大工程成本）

现状 main.js `selected` Map 以 DOM 引用为键，翻页整表重建后 `pruneDetached()` 会剔掉选中项。改造方向：

- 采集期间冻结 prune（`exporting` 期间已有同款跳过先例）；
- 采集完成后表格条目以**逻辑表格**（快照 + 定位器）存在，不以 DOM 引用为键——对齐虚拟表 `snapshots` Map 的「快照为真相」模式；
- 导出链路读取快照（`doExport` 已有 `snapshots.has(table)` 分支，扩展为逻辑表格通用）。

## 拦截语义冲突处理

| 场景 | 处理 |
|---|---|
| 子选择模式（指定按钮） | 拦截所有点击（比 v2.4 宽），明确提示；Esc 退出 |
| 采集期间扩展点击分页按钮 | 豁免链接拦截——分页器常为 `<a href>`（ant-pagination / jQuery 插件），编程式 `.click()` 须放行；豁免范围仅限已识别/指定的翻页按钮本身，其余链接拦截不变 |
| 采集期间用户点击 | 与虚拟采集一致：全拦截 + 2s 节流 toast |

## 复用资产清单

| 现有机制 | 翻页场景对应 |
|---|---|
| collectVirtual 的重叠合并 + 行签名 | 窗口粒度从滚动窗口换成页，算法不变 |
| genToken + 「停止采集」 | 翻页采集同款中止，零新增状态机 |
| openBatch 批量取值 | 逐页取值直接受益 |
| tableKeyOf 表头指纹 | 逐页校验「还是同一个表」 |
| GRID_ADAPTERS 注册表模式 | 分页适配器复制该模式 |
| snapshots 快照 Map | 采集结果落点，列设置/导出链路零改动 |

## 边界与降级

- 翻页触发整页导航（SPA 路由级跳转，非数据替换）→ 识别到导航发生即中止，toast 说明不支持（首版接受）；
- 表头指纹逐页突变 → 中止并保留已采页 + toast，安全降级；
- 每页行数极少且页数极多的分页（如每页 10 条 × 500 页）→ 采集耗时长，hint 实时进度 + 可中止兜底；
- 指定按钮后页面改版 → 定位器解析失败，引导重新指定。

## 落地路径

| 阶段 | 范围 |
|---|---|
| MVP（v2.5 已实现） | 第一层（el-pagination + ant-pagination 两适配器）+ 第三层（用户指定）+ 采集主链路（选区快照改造、拦截豁免、停止条件）；test/ 新增三个分页 fixture（el / ant / 自建分页器），浏览器回归对照页内预期值 |
| 二期 | AG Grid 适配器、第二层语义启发（观察 MVP 实际使用命中情况再定优先级）、指定按钮定位器持久化、滚动页码跳转输入框 |
| 同步义务 | 实现时按 AGENTS.md：manifest 版本号、architecture.md（模块表 + 关键机制）、product.md（用户故事 + 交互规范 + 已知限制）、test/README 同步更新 |

## 风险小结

- 算法层无硬障碍（重叠合并对「无重叠页」天然兼容）；
- 工程成本集中在选区管理改造（selected Map 键语义变化，波及 main.js 多处）与跨页重定位；
- 识别通用性经三层策略化解为体验问题（识别不到多一步用户操作，功能始终可用）。
